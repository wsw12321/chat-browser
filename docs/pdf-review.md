# PDF.js 固定版本只读审查

本仓库固定 `pdfjs-dist 6.3.289`，使用 `patches/pdfjs-dist@6.3.289.patch` 及 pnpm 的 `patchedDependencies` 锁定补丁哈希。升级时不能沿用旧审查结果：必须更新解析器版本、补丁、依赖锁并重跑全部覆盖样本。依赖的 API 与构建内代码已本机核查；版本查询来源为 npm 官方 registry 的 `pdfjs-dist` 元数据。

## 补丁为什么必要

上游 `Catalog.openAction` 将原始动作转换为 `dest` 或 `action`。转换可能丢弃启动、提交、URI 等动作，单靠 `getOpenAction()` 的空返回不能证明没有主动动作。补丁增加 `PDFDocumentProxy.getWebchatReview(pageIndex?)` 和对应消息处理器，仅返回版本、检查结果、固定错误码及检查计数，不修改解析、渲染、动作执行或文档内容。

原始检查包括 Catalog 的 `OpenAction`、`AA`、动作 `Next` 链、JavaScript/EmbeddedFiles 名称树、AcroForm/XFA、关联文件和 Outlines，以及逐页原始 Annots/AA、填写控件、文件附件、媒体和三维批注。另对 Catalog 可达字典及数组做有界只读遍历，发现位于结构树、Popup 父对象或其他关联位置的 Filespec、EmbeddedFile 和主动动作；不读取或解码流正文。上游 `xref.countUpdatesAfter(0)` 返回无法验证的结果时拒绝经过修复或不完整交叉引用的文件。存在 Encrypt 标记的文档均拒绝，包括能使用空密码读取的文档。

原始结构审查额外使用 50,000 个可达边/容器、64 层结构深度上限；它们属于初版版本化策略的一部分。达到检查上限的文件拒绝，不截取后续结构。正常 PDF 的父引用循环会去重；动作链循环或无法可靠取得的结构拒绝。普通页内 GoTo 和明确的前后翻页 Named 动作允许；URI、远程跳转、打印等其他动作保守拒绝。

## 运行与终止

PDF.js 主 API 与解析核心一起打包到 `/parsers/` 的浏览器 Dedicated Worker 中。导入核心后，PDF.js 使用已注册的内存 loopback 端口；不生成 Blob 脚本，也不创建无法被宿主收回的子 Worker。只读检查及提取不使用渲染器，不执行 PDF 内脚本，不启用 XFA/WASM，不访问网络、不加载附件 URL，不调用 OCR。

PDF.js 6 依赖新的 Map 插入方法及 Uint8Array 十六进制方法。`pdf-runtime.ts` 提供固定、无 eval 的最小实现，仅在可销毁解析 realm 内使用，不修改页面 realm。该兼容处理不改变 PDF 审查规则。

主页面拥有独立的总任务 15 秒计时器和每页 2 秒计时器，超时直接 `Worker.terminate()`。文件读取也在该 Worker 内进行。适配器在正常结束与错误时销毁加载任务、取消文字流、清理页面；图片位图及 Canvas 有各自的清理路径。第三方解析器仍没有独立的进程级内存配额，不能据此宣称恶意文件绝不会耗尽浏览器内存。

## 接受范围与拒绝范围

普通、有足够文字层、可独立本地提取的 PDF 进入文字预览。每页最多 20,000 个文字项，总计 100,000 项；文字不足页遵循设计文档的 OCR 判定；所有 PDF 均需确认图表、图片和部分排版损失。加密、主动动作、表单、关联文件、修复交叉引用、必要资源缺失或任何检查失败都会拒绝。

未提供网络 CMap、字体或 WASM 资源。如果文件必须依赖包外资源才能可靠提取，返回 `document_unverifiable`，要求重新导出带内嵌文字映射的 PDF。首版没有“忽略检查继续发送”选项。

DOCX 仅支持普通段落、列表和简单非嵌套、非合并表格；字段代码、隐藏文字、内容控件、备用表示、特殊字体符号、修订、批注和未处理文本框会保守拒绝，避免静默丢弃文字。页眉/页脚/脚注/尾注加来源标签，图片存在时要求确认未分析的损失。

## 自动化证据与发布门槛

`packages/file-review/test/pdf.test.ts` 使用真实合成 PDF 覆盖普通文档、页数、OCR、动作及动作链、名称树、填写控件、XFA、页面动作/批注、结构树附件、Popup 父附件及异常交叉引用。测试检查安装后的 API/worker 含相同补丁标识，并验证未打补丁或版本不匹配时拒绝。补丁不使用执行器，当前上游构建内也没有 `eval()`/`new Function()` 路径。

同包测试另覆盖 ZIP 声明与实际输出量、CRC、逐条目处理、DTD/非法编码/复杂度，图片预解码尺寸和静态容器检查，以及宿主真正终止 Worker。小型公开样本见 `tests/fixtures/README.md`。

自动测试通过才具备本地启用依据；正式浏览器、实际设备、真实大文件内存测量及 Gateway 联调仍须在发布验收记录中分别注明，不能用关闭 PDF 功能替代完整首版验收。
